# sebastianselman.ch

Static personal site. Plain HTML/CSS generated by a zero-dependency Node script,
served by GitHub Pages from `docs/`.

**You edit `content/`. You never edit `docs/`** — it is generated and wiped on
every build.

---

## Adding a talk, workshop or session

This is the thing you'll do most often. Open **`content/activities.json`** and add
one entry to the list:

```json
{
  "date": "2027-03-15",
  "title": "Title of the Talk",
  "kind": "talk",
  "venue": "Name of the Event, City",
  "url": "https://example.com/programme",
  "status": "confirmed",
  "blurb": "One or two sentences on what the session is about."
}
```

Then:

```bash
node build.mjs
```

Order in the file doesn't matter — entries sort themselves by date.

| Field | Notes |
|---|---|
| `date` | `YYYY-MM-DD`. Drives sorting and the "Previously" split. |
| `date_end` | Optional. `YYYY-MM-DD`, last day of a multi-day event. The card shows the range ("20–21 October 2026") and the entry stays upcoming until this date has passed. |
| `kind` | `talk`, `workshop`, `session`, `podcast` or `attending`. `attending` is for events you go to but don't speak at — labelled *Attending*, never *Talk*. |
| `url` | Link to the programme, write-up or recording. `null` if there isn't one. |
| `status` | `confirmed`, `tentative` or `past`. **See below.** |
| `blurb` | Optional. Markdown links and `**bold**` work. |

### The `status` field matters

- **`confirmed`** — shown on the page.
- **`past`** — shown under *Previously*.
- **`tentative`** — **hidden by default.** Nothing unconfirmed goes on a public
  page under your name without you saying so.

To preview all of them at once without publishing, set `_notes.show_tentative`
to `true` in `content/profile.json` — but set it back before deploying, or flip
the individual entries instead.

## Podcast episodes

The *Business Mission Control* episode list in `content/projects.json` keeps
itself current. Every night the rebuild workflow runs `sync-episodes.mjs`, which
reads the YouTube playlist feed and adds any episode the list doesn't have yet,
newest first, then the build and commit run as usual.

To run it yourself:

```bash
node sync-episodes.mjs --dry-run   # show what would be added, write nothing
node sync-episodes.mjs             # add new episodes to content/projects.json
```

- **It only ever adds.** Episodes are matched by YouTube video ID, and one that
  is already listed is never overwritten or removed, so hand edits stick: tidy a
  title or fix a date and it stays that way.
- **To drop an episode**, remove it from the playlist first, then delete its line
  from `projects.json`. Otherwise the next nightly sync adds it straight back.
- If YouTube is down or the feed changes shape, the sync prints a warning, leaves
  the file alone and the rebuild carries on. On GitHub the warning shows on the
  run's summary page.

New entries get the Zurich publish date, the title without the
" | Business Mission Control" suffix YouTube puts on some of them, and a
`slug` made from the title.

### Episode pages

Every episode has its own page at `/podcast/<slug>/`, and `/podcast/` lists
them all (the project's `"page": "/podcast/"` in `projects.json` switches this
on). A new episode's page exists from the night the sync adds it, with the
title, date and YouTube link. To give it show notes and a transcript:

1. Make a folder `content/podcast/<slug>/`, named exactly as the episode's
   `slug`.
2. Copy in `shownotes.md` and `transcript_website.md` from the delivery
   folder, unchanged. Nothing else in that folder is read or published, so
   never put the editor's final-cut file there.
3. `node build.mjs`.

The page then shows the summary and "We cover" list, chapters whose
timestamps open the video at that second, the sources as links, any notes,
and the full transcript with each timestamp linked the same way. The header
says "Hosted by Estera Kot and Sebastian Selman" (from `schema.cohosts` plus
your name): the Hosts line of the show notes and the speakers line at the top
of the transcript, both with job titles, are never shown.

| Episode field | Notes |
|---|---|
| `slug` | The page URL. Written once by the sync; **don't change it** after the page is live |
| `transcript` | `"provisional"` adds a note that the transcript comes from automatic captions and will be replaced. Delete the field when the editor's version is in |
| `same_as` | Optional. The episode on Spotify, Apple and the like: links on its page and in its structured data |
| `description`, `seo_title`, `length`, `modified` | Optional overrides. By default the description is the summary's first sentences (up to 160 characters), a title over 65 characters is cut at its first sentence break, the length comes from the show notes, and the sitemap uses `date` |

Episodes are numbered by date, oldest first. The build warns if a folder
matches no slug, if its show notes or transcript link a different video
(they are then left off the page), or if the show notes give another number.

The tests (`node --test`) use a local fixture feed and a temp copy of the file;
they never touch YouTube or the real `projects.json`.

| File | Holds |
|---|---|
| `content/profile.json` | Name, role, bio paragraphs, the links, the email address, the optional offer line and Invite section, and the facts behind the home page's structured data. See *The profile* below |
| `content/projects.json` | The Projects section. Podcast episodes sync themselves, see above |
| `content/podcast/<slug>/` | Show notes and transcript per episode, see *Episode pages* |
| `content/articles/*.md` | All 16 articles — 7 from limmatreframe.com, 9 from LinkedIn — one folder, one URL space |
| `content/career.json` | The career timeline — employers, roles, month spans |
| `content/certifications.json` | The Certifications section — Credly badges, advanced ones up front, the rest in a collapsed *More* group. To add one, see *Adding a certification* below |
| `assets/img/` | Images. Reference them as `/assets/img/name.jpg` |
| `assets/img/credly/` | The badge PNGs for the Certifications section |
| `assets/icons/` | Favicons, generated by `make-share-assets.py` |

Articles carry YAML front-matter:

| Field | Notes |
|---|---|
| `title`, `date`, `slug`, `byline`, `source` | As captured. The `slug` becomes the URL, so changing it breaks existing links — don't, unless you mean to |
| `origin` | `limmatreframe` or `linkedin`. Decides the credit line: *First published on limmatreframe.com, 2020* (plain text, because limmatreframe.com now redirects here) or *Also published on LinkedIn* (linked). The build stops on a file without it |
| `lang` | `en` (the default) or `de`. Sets `<html lang>`, `og:locale` and the schema's `inLanguage` |
| `topic` | `data-ai` (the default) or `earlier`. The group on the `/articles/` page |
| `description` | The search-result snippet, at most 155 characters, never ending in "…". Falls back to `summary`, then the first paragraph, cut to 160 |
| `seo_title` | Only where `title` plus " — Sebastian Selman" would pass 65 characters: a shorter title for the browser tab and search results. The name is still appended whenever it fits. The page heading keeps `title` |
| `modified` | Optional `YYYY-MM-DD`. Feeds `dateModified` and the sitemap's `<lastmod>`; without it, `date` does |
| `cover_image` | Optional. The share image; without it, the default share card |
| `translated_as` / `translation_of`, `translation_href`, `translation_lang` | The EN/DE twin, see *Notes on the content*. Also produces the hreflang links |

Until 30 October 2026 the limmatreframe.com pieces were served under
`/essays/<slug>/`, and limmatreframe.com's `.htaccess` still redirects there.
The build therefore writes a redirect stub at each old path, driven by the
`LEGACY_ESSAYS` list in `build.mjs`; the stubs stay out of the sitemap. Keep
the list for as long as that `.htaccess` points at the old paths. `/essays/`
itself and `/writing/` forward to `/articles/`, and `/reading/` (where
limmatreframe.com/resources/ lands) to the home page, since the Reading
section is gone.

## Search and sharing

Every page gets, from the templates in `build.mjs`:

- **One JSON-LD block** (`<script type="application/ld+json">`, an `@graph`).
  The home page describes the site, the profile page and the `Person`
  (`https://sebastianselman.ch/#person`), every project marked
  `"schema": { "type": "PodcastSeries", … }` in `projects.json`, and every
  upcoming, confirmed talk, workshop or session as an `Event` with Sebastian as
  performer. `attending` entries are not his events and stay out. Article pages
  describe an `Article` whose author is that `Person`.
- **Podcast platforms**: add Spotify, Apple and the like to the podcast's
  `schema.same_as` list, the RSS feed to `schema.web_feed`. No code change.
  The links then also show on the home page card, `/podcast/` and every
  episode page, named after the platform; nothing shows while the list is
  empty. The YouTube playlist is always a `sameAs`, since the series' own
  URL is `/podcast/`.
- **Podcast episodes**: each page describes a `PodcastEpisode` (part of the
  series, with its date, duration and the YouTube video as a `VideoObject`);
  `/podcast/` describes the series and lists every episode.
- **Events**: a venue starting "Online" (or `"mode": "online"`) becomes a
  virtual location. Optional `time_end` adds an end time; `address` a street
  address for an in-person venue.
- **Head tags**: `<html lang>`, canonical, hreflang for the twin pair,
  `og:image` (the article's cover, else `assets/img/share-card.jpg`),
  `og:site_name`, `og:locale`, `article:published_time` and
  `twitter:card=summary_large_image`.
- **Limits**: titles at most 65 characters (home 60), descriptions at most
  160. The build warns, the tests fail.

`/articles/` lists every article by topic, `/404.html` is what GitHub Pages
serves for an unknown path, and the sitemap carries a `<lastmod>` per URL.

The share card and the favicons come from the portrait and the name and role
in `profile.json`. After changing either:

```bash
py make-share-assets.py      # or python3; needs Pillow
node build.mjs
```

Slugs are folded to ASCII at build time (`ü` → `ue`, and so on). A raw umlaut in
a URL path 404s on GitHub Pages unless every href percent-encodes it — it works
locally and breaks live, which is the worst way to find out. Keep new image
filenames ASCII for the same reason.

### Adding a certification

1. On Credly, open the badge's share page
   (`https://www.credly.com/earner/earned/share/<badge id>`), choose
   **Download Badge**, then **Download Image**. If the dialog says the original
   is larger than 600 px, move the slider down to 600 first.
2. Save it as `assets/img/credly/<name>.png`, with an ASCII name.
3. Run `node strip-badge.mjs`. Credly bakes the full signed credential into the
   PNG; this drops it and leaves the artwork untouched. Visitors verify the
   badge on Credly instead, which is what the link is for. It also warns about
   anything over 600 px or 300 KB.
4. Add an entry to `content/certifications.json`:

   ```json
   { "name": "Badge Name", "issuer": "Issuer", "date": "2027-03-15", "expires": null, "tier": "advanced",
     "url": "https://www.credly.com/badges/<badge id>",
     "image": "/assets/img/credly/<name>.png" }
   ```

5. `node build.mjs`.

`tier` is `advanced` (shown up front, and the default when left out),
`foundational` (Microsoft Fundamentals, Google Cloud leader certifications) or
`hackathon`. Everything but `advanced` sits in the collapsed *More* group.

Order in the file doesn't matter — badges sort newest first by `date`. Set
`expires` (`YYYY-MM-DD`) for badges that lapse: once it has passed, the badge
stays listed and is marked *expired*, the same way Credly shows it. The build
warns if an entry's image is missing. EY badges are left off on purpose.

## The career timeline

`content/career.json` is a list of employers, newest first. Each has a `from`
and `to` in `YYYY-MM` (`null` for present) and a list of `roles` with their own
spans.

The chart positions each employer as a band across a year ruler, so overlapping
stints — the LimmatReframe consultancy ran alongside both BVS St. Gallen and
Microsoft — sit on their own rows and read as genuinely concurrent. Durations
are computed, not written: the end month counts as worked, which is the same
convention LinkedIn uses, so the figures agree with your profile.

Clicking a band opens that employer's roles. With JavaScript off, every detail
block is simply visible.

## Commands

```bash
node build.mjs
```

That's the build, every time. It writes `docs/` for the custom domain,
`CNAME` included.

`--base` exists only to preview the site under a GitHub Pages subpath. It drops
the CNAME, so **never deploy a `--base` build** — that took the site down on
26 August 2026.

To preview locally:

```bash
node build.mjs --serve
```

`--serve` builds and then serves `docs/` on <http://localhost:4173>, with the
custom 404 page for unknown paths, as GitHub Pages does.

Tests:

```bash
node --test
```

`test/build.test.mjs` builds into a temp directory (never `docs/`) and checks
every page: one parseable JSON-LD block, `lang`, no LinkedIn redirect links or
raw `[[n]]` citations, title and description lengths, share tags, the sitemap,
the 404 page and the favicon. A second build on a temp copy of `content/`
checks that the offer line, the Invite section, the events, a stub episode and
podcast platform links render from data
alone. `test/sync-episodes.test.mjs` covers the episode sync.

After adding large images:

```bash
python optimise-images.py
```

Caps the long edge at 1600 px and re-encodes anything over 300 KB. It keeps a
record in `assets/.optimised.json` so it never re-compresses the same file twice —
run it as often as you like.

## How it's published

GitHub Pages serves `docs/` from `main`, on repo `zxmaz/sebastianselman.ch`.
Push to `main` and the site updates within a minute or two.

**Live:** <https://sebastianselman.ch>, on the custom domain.

`docs/CNAME` holds the custom domain. `docs/.nojekyll` stops GitHub trying to run
Jekyll over the output.

**DNS:** the apex `A` records point at GitHub Pages (`185.199.108.153`,
`.109.153`, `.110.153`, `.111.153`) and `www` at `zxmaz.github.io.`, both set
at all-inkl. The cutover is done (Work Item #190, 26 August 2026).

The `MX` record stays on all-inkl. Mail is unaffected.

## Notes on the content

The articles were recovered from limmatreframe.com and LinkedIn under Work
Item #189. The full archive — including images, page HTML and the WordPress
REST payloads — lives outside this repo in `Web/archive/`.

Two pairs are deliberately not what they look like:

- **"What is at the core of a persona?"** existed on both platforms; the
  limmatreframe version is published here and the LinkedIn original is credited
  in its front-matter.
- **"Grenzen erreichen. Grenzen überwinden."** (German, Nov 2019) and **"Heroes,
  fools and design thinkers meet outside the box"** (English, Jan 2020) are the
  same piece in two languages. Both are published and cross-linked. Automated
  similarity can't detect this — the two share almost no vocabulary — so the link
  is recorded by hand in the front-matter and has to stay there.

Earlier work carries the **Sebastian Rappen** byline, which the site shows
explicitly rather than quietly rewriting.
