# sebastianselman.ch

Static personal site. Plain HTML/CSS generated by a zero-dependency Node script,
served by GitHub Pages from `docs/`.

**You edit `content/`. You never edit `docs/`** — it is generated and wiped on
every build.

---

## Adding a talk, workshop or session

This is the thing you'll do most often. Open **`content/activities.json`** and add
one entry to the list:

```json
{
  "date": "2026-11-16",
  "title": "The Effort Illusion",
  "kind": "talk",
  "venue": "Swiss AI Summit, Kunsthaus Zürich",
  "url": "https://example.com/programme",
  "status": "confirmed",
  "blurb": "One or two sentences on what the session is about."
}
```

Then:

```bash
node build.mjs
```

Order in the file doesn't matter — entries sort themselves by date.

| Field | Notes |
|---|---|
| `date` | `YYYY-MM-DD`. Drives sorting and the "Previously" split. |
| `kind` | `talk`, `workshop`, `session` or `podcast`. |
| `url` | Link to the programme, write-up or recording. `null` if there isn't one. |
| `status` | `confirmed`, `tentative` or `past`. **See below.** |
| `blurb` | Optional. Markdown links and `**bold**` work. |

### The `status` field matters

- **`confirmed`** — shown on the page.
- **`past`** — shown under *Previously*.
- **`tentative`** — **hidden by default.** Nothing unconfirmed goes on a public
  page under your name without you saying so.

Two entries are currently `tentative`: the SWAIS keynote (submission status was
tentative) and the WAVE Fellowship workshop (date not yet confirmed by Hilda).
When either firms up, change that entry's `status` to `confirmed` and rebuild.

To preview all of them at once without publishing, set `_notes.show_tentative`
to `true` in `content/profile.json` — but set it back before deploying, or flip
the individual entries instead.

## Everything else you might change

| File | Holds |
|---|---|
| `content/profile.json` | Name, role, bio paragraphs, the LinkedIn/GitHub/email links |
| `content/projects.json` | The Projects section |
| `content/essays/*.md` | The 7 limmatreframe.com essays |
| `content/articles/*.md` | The 9 LinkedIn articles |
| `content/reading.md` | The book list |
| `assets/img/` | Images. Reference them as `/assets/img/name.jpg` |

Essays and articles carry YAML front-matter (`title`, `date`, `slug`, `byline`,
`source`). The `slug` becomes the URL, so changing it breaks existing links —
don't, unless you mean to.

Slugs are folded to ASCII at build time (`ü` → `ue`, and so on). A raw umlaut in
a URL path 404s on GitHub Pages unless every href percent-encodes it — it works
locally and breaks live, which is the worst way to find out. Keep new image
filenames ASCII for the same reason.

## Commands

```bash
node build.mjs --base sebastianselman.ch
```

**Use `--base` for now.** Until DNS points the domain at GitHub, the site is
served from a subpath (`zxmaz.github.io/sebastianselman.ch/`), where
root-absolute links would 404. The flag prefixes internal links and skips the
CNAME, because a custom domain and a subpath cannot both apply.

Once the DNS cutover lands (Work Item #190), drop the flag permanently:

```bash
node build.mjs
```

To preview locally:

```bash
node build.mjs --serve
```

`--serve` builds and then serves `docs/` on <http://localhost:4173>.

> On Git Bash, pass the base **without** a leading slash. Git Bash rewrites
> `/sebastianselman.ch` into a Windows filesystem path; the build detects that
> and warns, but the clean form avoids the noise.

After adding large images:

```bash
python optimise-images.py
```

Caps the long edge at 1600 px and re-encodes anything over 300 KB. It keeps a
record in `assets/.optimised.json` so it never re-compresses the same file twice —
run it as often as you like.

## How it's published

GitHub Pages serves `docs/` from `main`, on repo `zxmaz/sebastianselman.ch`.
Push to `main` and the site updates within a minute or two.

**Live now:** <https://zxmaz.github.io/sebastianselman.ch/>

`docs/CNAME` holds the custom domain. `docs/.nojekyll` stops GitHub trying to run
Jekyll over the output.

**DNS:** `sebastianselman.ch` must point its apex `A` records at GitHub Pages
(`185.199.108.153`, `.109.153`, `.110.153`, `.111.153`) and `www` at
`zxmaz.github.io.`. That change happens at all-inkl and is tracked as Work Item
#190 — until it lands, the site is only reachable at `zxmaz.github.io`.

The `MX` record stays on all-inkl. Mail is unaffected by the switch.

## Notes on the content

The essays and articles were recovered from limmatreframe.com and LinkedIn under
Work Item #189. The full archive — including images, page HTML and the WordPress
REST payloads — lives outside this repo in `Web/archive/`.

Two pairs are deliberately not what they look like:

- **"What is at the core of a persona?"** existed on both platforms; the
  limmatreframe version is published here and the LinkedIn original is credited
  in its front-matter.
- **"Grenzen erreichen. Grenzen überwinden."** (German, Nov 2019) and **"Heroes,
  fools and design thinkers meet outside the box"** (English, Jan 2020) are the
  same essay in two languages. Both are published and cross-linked. Automated
  similarity can't detect this — the two share almost no vocabulary — so the link
  is recorded by hand in the front-matter and has to stay there.

Earlier work carries the **Sebastian Rappen** byline, which the site shows
explicitly rather than quietly rewriting.
